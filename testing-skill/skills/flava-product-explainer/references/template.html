🏗️ Quản lý Service (Cluster) ▼

Toàn bộ vòng đời của một cluster OpenSearch được quản lý qua giao diện hoặc API:

  • Tạo service: Chọn engine version, node flavor (CPU/RAM), số lượng node, Availability Zone để đảm bảo high availability
  • Gia hạn thời hạn: Cluster có thời hạn sử dụng — có thể gia hạn bất cứ lúc nào
  • Xóa service: Dọn dẹp hoàn toàn khi không còn cần
  • Monitor trạng thái: Polling real-time status (Running, Creating, Deleting...)
📑 Quản lý Index & Index Template ▼

Index là nơi lưu trữ dữ liệu — tương tự như "bảng" trong database quan hệ.

  • Index Template: Blueprint cho index — định nghĩa schema, mapping fields (đặc biệt là knn_vector field)
  • Visual mode: Cấu hình field knn_vector bằng giao diện (chọn engine, space type, dimension...)
  • Code mode: Viết raw JSON mapping cho người dùng advanced
  • Index Patterns: Một template có thể áp dụng cho nhiều index theo pattern wildcard
🤖 ML Model Catalog ▼

Trung tâm quản lý embedding model cho vector search:

  • Model Catalog: Danh sách model đã được kiểm duyệt, sẵn sàng sử dụng
  • Đăng ký (Register): Gắn model vào một service cụ thể
  • Deploy/Undeploy: Bật/tắt model trên cluster — tiết kiệm tài nguyên
  • Liên kết pipeline: Xem model đang được dùng bởi pipeline nào
💡 Ví dụ: Model "multilingual-e5-small" chuyển văn bản tiếng Việt thành vector 384 chiều, hỗ trợ tìm kiếm đa ngôn ngữ
⚙️ Pipeline (Ingest & Search) ▼

Pipeline là "dây chuyền xử lý" dữ liệu — định nghĩa cách dữ liệu được biến đổi khi lưu vào và khi tìm kiếm:

  • Ingest Pipeline: Xử lý document khi đưa vào index — ví dụ: gọi ML model để tạo vector từ text
  • Search Pipeline: Xử lý query khi tìm kiếm — ví dụ: chuyển query text thành vector, hybrid scoring
  • Visual Editor: Kéo thả processor, xem flow trực quan — không cần JSON
  • Simulate: Test pipeline với dữ liệu mẫu ngay trên UI, không cần deploy thật
🔐 Bảo mật: DB Role & User ▼
  • DB Role: Định nghĩa quyền truy cập theo index pattern — read, write, create index...
  • Field-level Security: Ẩn/cho phép chỉ đọc các field cụ thể
  • Document-level Security: Chỉ xem document thỏa điều kiện nhất định (ví dụ: chỉ xem data của tenant mình)
  • System Account: Tài khoản dịch vụ để ứng dụng kết nối
  • IAM User: Gắn người dùng Flava IAM với DB Role
